Curfew for Windows
==================

What is in this folder
----------------------

  curfew.exe        the service and the command line.
  curfew-app.exe    the window: what is running, what is planned, whether it is working.
  curfew-tray.exe   the tray icon: what is blocked now, and the overlay when something is.
  LICENSE           AGPL-3.0-or-later. The source is the release this was built from.
  INSTALL.txt       this file.


Installing
----------

Use the installer. curfew-x64.msi (or curfew-arm64.msi) is on the same release page as this
archive; double-click it, approve the one Windows prompt, and it is done. It puts the programs in
C:\Program Files\Curfew, registers the Windows service, adds Curfew to the Start menu and starts
the tray icon. Nothing has to be typed. Uninstalling is done from Settings > Apps like anything
else, subject to the refusal described below.

    winget install Curfew.Curfew

does the same thing from a package manager, if that is how you prefer to install things.

This folder is the other way: the files on their own, for placing by hand or for scoop. If you
took that route, the service still has to be registered once:

1. Put this folder somewhere permanent. C:\Program Files\Curfew is the usual choice, but any
   path works — the service remembers where it was registered from, so moving the folder
   afterwards breaks it until you register it again.

2. Open a terminal as administrator and run:

       curfew install

   That registers the Windows service, starts it, and sets the tray to run at login. A service
   is needed because a blocker that a task manager can close is not a blocker.

3. Check it came up:

       curfew status

`curfew install` also adds one Windows Firewall rule, named "Curfew (device sync)", allowing
curfew.exe to accept connections on private and domain networks. That is how your own devices
find each other; without it Windows asks for an administrator every time the service restarts.
It is not added for public networks, and `curfew uninstall` removes it again. To do without it,
delete the rule in Windows Defender Firewall — syncing between devices stops, and nothing else
changes.

Until this machine is paired with another device, Curfew opens no port at all: an unpaired
device has nothing to say and nobody to say it to, so it does not listen and Windows has no
reason to ask about it. The listener starts within half a minute of the first pairing.


Blocking a page rather than a whole site
----------------------------------------

A rule like *youtube.com/shorts* names a page, and nothing outside the browser can see which page
a tab is on. For those rules Curfew needs its extension, in the extension/ folder of the source:

  1. Load it as an unpacked extension in your browser and copy the id it is given.
  2. Register it, from an ordinary terminal — no administrator needed:

         curfew extension chrome <extension-id>

     chrome, edge, brave, vivaldi, chromium, firefox and librewolf are understood. Do this once
     for every browser you use.

While a page-level rule is running, a browser that is not reporting is closed. That is deliberate:
removing the extension has to cost you the browser, or it would be a way around the rule. Rules
that name whole sites or apps need none of this.


Uninstalling
------------

Settings > Apps > Installed apps > Curfew, if you used the installer. Or, either way:

       curfew uninstall

This is refused while a lock is running, and that refusal is the product working. If you are
locked and you want out, start the way out and wait for it:

       curfew release <session-id>

The release takes 24 hours. Nothing shortens it — not reinstalling Windows, not deleting the
files, not the developer. That is the promise you made to yourself when you started the block,
and Curfew keeping it when you no longer want it kept is the only reason it is worth running.

If the machine is genuinely unusable and you need out now, you can still sign in with your
Windows password wherever a block offers a credential unlock, if the profile allowed one.


Your antivirus may object
-------------------------

Curfew does several things that malware also does: it installs a service that restarts itself,
it closes other programs, it edits the hosts file, and (if you turn the resolver on) it points
your DNS at itself. Those are the blocking mechanism. There is no version of a distraction
blocker that does not look like this to a heuristic.

So expect one of these:

  * SmartScreen: "Windows protected your PC" on first run. These builds are not signed with an
    EV certificate — that is a few hundred dollars a year, and Curfew has no revenue. Click
    "More info", then "Run anyway", after you have checked the hash below.

  * Defender or a third-party scanner flagging curfew.exe, usually as a generic
    "Trojan:Win32/Wacatac" or "Agent" detection. These are unsigned-binary heuristics, not a
    match against known malware.

Do not just click through it. Verify the download instead:

    certutil -hashfile curfew-x64.msi SHA256
    certutil -hashfile curfew-x64.zip SHA256

and compare that against the SHA256SUMS file on the release page. If they match, the archive is
byte-for-byte what the public GitHub Actions run built from the tagged source. If they do not
match, delete it and tell us — that is the case that actually matters.

If you want to be more careful than that, build it yourself. That is the whole point of the
licence:

    cargo build --release -p curfew-svc -p curfew-tray

To submit a false positive to Microsoft:
https://www.microsoft.com/en-us/wdsi/filesubmission


What Curfew touches on this machine
-----------------------------------

  * A Windows service, "Curfew", set to restart on failure.
  * A run-at-login entry for the tray.
  * %PROGRAMDATA%\Curfew — the config, the sessions, and the state.
  * The hosts file, while a website block is running. Curfew's lines are marked and only
    Curfew's lines are removed.
  * Your per-interface DNS settings, but only if you turned the resolver on in the config.
    What they were before is written to dns-before.json first and given back on uninstall,
    including if the service was killed rather than stopped.

Nothing is sent anywhere. There is no account, no server, and no telemetry. Sync, when you turn
it on, goes device to device.
